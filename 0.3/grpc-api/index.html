The gRPC API

The gRPC API

The API is gRPC, proto/turn/v1/turnd.proto (service turn.v1.Turnd). The generated code is committed, and CI regenerates it and fails on a diff.

Transport

A plain grpc.Server is served over a WebSocket at /grpc (grpc-transports/websocket), which is what a browser can speak, including the bidirectional stream.

The WebSocket upgrade enforces the exact origin allowlist (--allowed-origin; scheme and port included). A client with no Origin header is a native client.

Tokens

A token travels as authorization: Bearer … metadata, never in a URL.

HTTP, for browser navigations

Status codes

A message that breaks the protocol (too large, a spoofed from, a bad kind, a pending sender, guest to guest) ends the sender’s stream with a status: RESOURCE_EXHAUSTED, PERMISSION_DENIED, INVALID_ARGUMENT. Other refusals:

The Go client

For the browser and native: github.com/go-turn/turn/rendezvous/client. Create, Join(name) (blocks until admitted, ErrDenied otherwise), Admit, Deny, Send, Recv, Credentials, Close.

It is a real grpc-go client dialed over the browser’s WebSocket through syscall/js. It adds about 16 MB to a wasm binary (3.5 MB more gzipped), almost all of it grpc. go-crdt/collab’s js/wasm build does not link grpc, so a page that does not otherwise ship it should load this client in a separate wasm, fetched when a collaboration starts.
